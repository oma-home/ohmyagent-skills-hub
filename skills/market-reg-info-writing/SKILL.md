# 市场监管总局信息稿写作

使用本 skill 协助起草或修改报送市场监管总局（SAMR）的信息稿，重点是标准创新管理司（创新司）和科技和信息化司（科信司）口径的材料。

## 快速工作流

1. **先判明对口司局**
   - 用户提到 创新司 / 标准创新司 / 标准创新管理司：套用"标准 / 规则 / 标准化"口径。
   - 用户提到 科信司 / 科技和信息化司：套用"科技 / NQI / 信息化 / 智慧监管 / 技术机构"口径。
   - 用户未明示时，根据主题推断并明确告知用户推断结果。

2. **再判明信息稿类型**
   - 国外最新法规、标准、认证、贸易壁垒、海外治理动向：**涉外信息**（再分"国外动向类"与"国际经验类"，各有长短篇）。
   - 具体风险、瓶颈、企业困难、监管短板：**问题信息**。
   - 数据集、清单、监测结果、统计结果、可图表化的分析：**数据信息**。
   - 即将出台的政策、文件、专项行动、重要部署：**正面信息（部署类）**。
   - 已完成工作、阶段性进展、典型案例、示范经验：**正面信息（总结类 / 案例示范类）**。
   - 地方一线观察、企业诉求、地方平台动向：**基层反映**。

3. **按需加载参考资料**
   - 类型选择、刊物体系、报送要求、标题公式、对策建议母式：读 `references/info-types-and-reporting.md`。
   - 起草或修改稿件、套用具体类型模板卡：读 `references/writing-template-cards.md`。
   - 司局职责、关注重点、口径差异、同主题切换：读 `references/office-focus.md`。

4. **按用户要求产出**
   - **提纲**：给出若干标题备选、目标司局、信息稿类型、主体结构、建议证据。
   - **初稿**：按公文信息稿体例撰写，要素包括清晰标题、帽段、主体逻辑、对策建议段。
   - **修改**：依次诊断标题、帽段、结构、证据、司局口径、对策建议段；然后给出修改稿。

## 司局口径判别规则

报 **创新司** 的核心议题通常是：

- 标准、国际标准、ISO/IEC/ITU、标准制定、标准实施监督；
- 标准化合作、金砖、共建"一带一路"、全球南方、规则"软联通"；
- 由标准、认证、合格评定、技术法规构成的技术性贸易壁垒；
- 把我国技术优势转化为标准或国际规则话语权。

报 **科信司** 的核心议题通常是：

- 科技赋能市场监管、智慧监管、数字化监管平台、监管数据共享；
- NQI 重大科技需求、科研攻关项目、技术机构；
- 重点实验室、技术创新中心、技术验证、检验检测、模型评估；
- AI 安全评测、可信可控 AI、监管智能体、数据集、模型验证。

当主题两边都沾时，按主问题判断：

- 规则制定和标准话语权 → 创新司；
- 技术支撑和信息化能力 → 科信司。

## 写作风格要求

- 用简洁的公文信息稿语言，避免铺陈。
- 标题和帽段必须把核心政策判断亮出来，做到"师出有名"——必要时在帽段点出中央领导指示批示、党中央国务院部署或重要政策文件。
- 证据要实：每个问题尽量列 2 个以上例子，避免"孤证"；多用日期、数字、国外政策名称、标准编号、机构名称、行业影响、地方案例。
- 不要写"加强监管、完善机制"这类空话，除非紧跟具体的责任部门、工具和抓手。
- 对策建议段必须区分两类对象：
  - "建议……等部门"——写给其他部委或责任部门；
  - "市场监管总局将……" 或 "依托……技术创新中心……"——写给市场监管系统自身的下一步动作。

## 交稿前的自检清单

- 标题是否与信息稿类型匹配（问题导向 / 部署导向 / 进展导向 / 数据导向 / 涉外动向）？
- 帽段是否说明了"为什么这件事值得报两办或市场监管总局"？
- 主体结构是否符合对应类型的模板（短篇不设"一、二"大标题，长篇才分一级标题）？
- 每个问题或动向是否都有案例或数据支撑？
- 对策建议段是否点到了具体责任部门或技术机构？
- 整体用词是否反映了对口司局口径（创新司偏"标准 / 规则 / 互认"，科信司偏"科技 / 智慧监管 / 评测验证"）？
- 涉外稿的时效是否合规（单个动向是"近日"，综合动向是"近期"）？
